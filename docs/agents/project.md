# 專案客製規範

本檔由專案維護，初始化只在不存在時建立，更新上游時保留。規劃與交付前讀取；未填內容從 repo 的設定、現有文件與命令取得，不為填表猜測。

## 專案邊界與驗證入口

填入實際模組邊界、可用的 build／test／lint 命令，以及必要的環境限制；設定檔能直接提供的內容可只寫位置。

## 提交與交付

優先採專案提交規範；未定義時使用 `type(scope): 中文摘要`，issue 編號放 footer `Refs: #ID`。PR base 由現有 PR 或專案設定取得；無法確定才詢問。分支以 issue-ID 加描述為預設，可依既有慣例調整。使用 worktree 時記錄其位置格式，以及遠端需要 token 時的取得方式與使用者名（只寫取得方式，不寫 token 本身）。記錄合併判定方式（例如平台 MR merged 狀態，或 rebase 併入時以 commit subject 的 issue 編號為準）。dev-cycle 懸置掃描可另登記：唯讀掃描命令（輸出格式見 dev-cycle 技能的 `references/pending-scan.md`）、含已關閉 issue 的平台查詢命令、掃描起點（issue 編號或日期），以及本專案對收尾、文件債或排除的判定規則（優先於 kit 的偵測規則）。

## 常青文件更新責任

用專案實際路徑建立「變更 → 文件」對照：部署拓撲／路由與依賴 → 架構文件；領域規則／實體關係 → 領域文件；部署／告警 → 操作文件；使用者功能 → 使用手冊。只列已有或此次確實需要建立的文件；交接或上手文件同樣登記觸發條件，例如新增外部服務、帳號、部署單元或本機建置步驟。

## 本地 gate 與案例

記錄專案特有的前置條件、需由使用者決定的事項與規模門檻，作為每個 issue 都要遵守的 gate。已知地雷依 document-types.md「地雷紀錄」寫在本節，或記錄獨立地雷檔的路徑與何時讀。保留核心的誠實回報、核准來源與證據要求。
