## 觀察

- WF-19 正向的第 3 輪曾說「多帶參數」的假設「寫進驗收條件，不另外問」，第 4 輪改為列待核准並提問。結果符合 acceptance.md（新行為需核准），但前後說法不一致。
- 案例定義寫 Medium，兩組 agent 都判為 Small。逐題確認不依規模而變，判定不受影響。
- WF-20 正向把結論寫在待確認事項的「狀態」欄（`已解決 — …`），與 AGENTS.md 狀態值與結論分開的寫法略有出入，資訊完整。
- 設計 fixture 時發現規則缺口（未實跑）：dev-cycle 寫「接受未修的 MUST FIX 記入 Gate 豁免紀錄」，但沒說之後報告仍為 RETURN 時如何推進，可能落回「有效 review 為 RETURN TO execute-task」那一列。同日已補規則（PASS 條件與重新 review），修正本身未實跑。

## 限制

- 無頭模式停用了 AskUserQuestion，提問一律走文字；Claude Code 互動模式以 AskUserQuestion 提問的路徑未測。
- Bash 只允許部分命令前綴，含管線或 `;` 的複合命令被擋，agent 改以單一命令完成；不影響判定。
- 測試 session 會載入操作者的全域 CLAUDE.md 與 MCP（serena 在 fixture 產生 `.serena/`）。
- 每個案例只跑一次、單一宿主與模型；Codex、OpenCode、Antigravity、Cursor 未測。
