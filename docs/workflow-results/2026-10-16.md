# 地雷紀錄、懸置掃描與合併後觀察回歸 — 2026-10-16

本紀錄驗證 v4.6.0 新增的 WF-21～WF-23。案例定義見 [workflow-regression.md](../workflow-regression.md)，規則狀態回寫 [rule-verification-status.md](../rule-verification-status.md)。

## 環境

- kit：`5f59a60` 加上 v4.6.0 的未提交修訂（技能與 `docs/` 皆為當時的工作樹版本）。
- 宿主：Claude Code 2.1.301，`claude -p` 無頭模式，每組案例一個新 session、只跑一輪；操作者不追加回答。
- 模型：`claude-opus-5-5`（取自各輪輸出的 `modelUsage`）。
- 技能隔離：以獨立的 `CLAUDE_CONFIG_DIR` 執行，其中的技能由 `install.sh claude` 從工作樹安裝；未載入操作者的全域 CLAUDE.md、全域技能與 MCP。全域已安裝的 v4.5 技能未被改動。
- 工具權限：Read、Edit、Write、Glob、Grep、Skill，Bash 只允許 `git`、`python3`、`ls`、`cat`、`date` 開頭的命令。
- fixture：拋棄式 Git 專案（待辦 CLI `todo.py`＋unittest），以 `init-project.py` 部署流程契約 2.2，`project.md` 已填寫（含一條既有地雷、無遠端平台時以 `--no-ff` 合併代表 PR merged、Proof 表寫在 README `## 驗證`）。由腳本建立於 session scratchpad，非永久產物。

## 觀察

- 第一輪的 WF-22、WF-23 fixture 有缺陷：合併的分支只含佔位檔，沒有 README 宣稱的實作與測試，建立日期也晚於合併日。四個 session 全部改為唯讀回報「證據與程式碼不一致」，不結案、不轉狀態。該輪作廢，修正 fixture 後重跑（上表為重跑結果）；但這說明「完成判準是證據與狀態一致」在合併後的分支也會擋下。
- WF-23 兩組都主動指出 project.md 規定的使用說明沒有隨新指令更新，並請使用者決定，沒有自行補寫或重開實作。
- WF-21 正向想實際執行 CLI 確認 `[x]`，命令被本次的工具權限擋下，改為照實回報未驗證的部分。
- WF-23 正向的最終回報是英文，其餘為中文。隔離設定未載入操作者的全域語言偏好，fixture 也沒有規定語言；不影響判定。

## 限制

- 每個案例只跑一輪、單一宿主與模型；Codex、OpenCode、Antigravity、Cursor 未測。互動模式的 AskUserQuestion 路徑未測。
- 無遠端平台：「PR 已 merged」以本機 `--no-ff` merge commit 代表；平台 PR 狀態與 project.md 登記平台查詢命令的分支未測。
- WF-21 只測到「該寫地雷時寫、不該寫時不寫」與「沒有追蹤位置時提問」；地雷改為獨立檔案、私人記憶升格兩個分支未測。
- 「窗口已不會再出現時回報、由使用者決定豁免」的分支未測。
