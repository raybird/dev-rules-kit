## 觀察

- **v4.9.0 的 agent 本來就會重跑查證**。wf29 系列的三個變體（README 現況過時、查證失敗、舊格式且未登記命令）兩組行為相同，「外部狀態以實查為準」在本次實跑沒有可觀察的效果。下游回報的失敗發生在長 session、跨 session 記憶與他人回報累積的情境，本組 fixture 是單一 session、回報只有一句話，沒有重現那個條件。
- **wf32 的判準比 SCN-007 寬**。寫定的判準只在「沒有 README 連結或查證」時判失敗；SCN-007 原文只容許連結與錨定 commit 的事件。照原文，兩組的帶日期查證表都還是狀態副本。2026-11-11 使用者決定維持原文，兩組既有輪次照原文重判為未符合；重判依證據檔與本紀錄的描述，原始 stream-json 已不在暫存區。
- **交接文件會讓 PASS 失效**。兩組在 wf32 都沒照指示提交，原因相同：`docs/handover.md` 在 issue 目錄外，提交到 issue 分支會讓 PASS 失效。兩組都先請使用者選提交位置。
- **自述與實際做法不一致**。wf33 兩組都說「逐一讀過」，實際以 grep 判定；結構化的偵測規則能用 grep 一次判完，讀不完的情境沒有出現。
- **隔離漏洞**。候選組 wf30c 的 agent 以 Glob 在 kit 工作樹找到 `verify-artifact.py` 並執行，沒有用隔離設定的那份；兩份內容相同，判定不受影響。
