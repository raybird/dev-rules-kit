**Q2. 到期時間的格式**（AC：設定、到期判定）
- 建議：`YYYY-MM-DD HH:MM`，用本機時間，精確到分鐘。
- 理由：只支援一種格式，解析和測試都最單純。

**Q3. 怎麼設定到期時間**（AC：設定）
- 做法 a（建議）：新增 `todo.py due <id> <YYYY-MM-DD HH:MM>`。這個指令也能幫已經存在的待辦設定到期時間，而且不用改 `add` 現在「把剩下的參數全部當標題」的解析方式。
- 做法 b：在 `add` 加 `--due`。新增時一步就能設定，但要改標題的解析方式，舊項目也沒辦法補設。
- 重複對同一個項目執行 `due`，會覆蓋掉原本的時間。

**Q4. 輸入錯誤時怎麼處理**（AC：失敗路徑）
- 建議：時間格式錯誤，或 id 不存在時，在 stderr 輸出錯誤訊息，exit code 不是 0，`todo.json` 不變。
- 理由：如果像現在的 `done` 那樣靜默略過，你會以為已經設好了，但其實沒有。

**Q5. 提醒的規則與格式**（AC：提醒）
- 只要目前時間大於或等於到期時間，而且項目還沒完成，就要提醒。
- 已完成的項目不提醒。
- 每次執行都會重複提醒，不記錄「已經提醒過」。
- 每個到期項目一行，格式為 `⏰ 已到期：3. 寫週報（到期 2026-10-18 09:00）`。
- 沒有到期項目時，不輸出任何額外內容。
- 舊 `todo.json` 裡沒有到期欄位的項目照常運作，不會提醒，也不會報錯。
- 以上全部照建議嗎？

**Q6. 清單要不要顯示到期時間**（AC：列出）
- 建議：有設定到期時間的項目，在行尾加上 `（到期 YYYY-MM-DD HH:MM）`；沒有設定的項目，輸出跟現在一樣。
- 理由：不然你沒辦法確認時間有沒有設好。現有的 `render` 測試不受影響。

**本次不做的事**（我會寫進文件裡）：清除或取消到期時間、時區設定、提前提醒。如果你需要其中哪一項，請直接說。
