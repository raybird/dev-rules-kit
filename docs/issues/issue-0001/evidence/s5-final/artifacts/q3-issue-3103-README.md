# Issue 3103 - 待辦刪除指令與復原 (Small)

## 概述
為 `todo.py` 新增刪除指令，刪除後可復原。CLI 每次執行都是獨立行程，被刪除的項目必須保存在磁碟上才能跨次執行復原。

現況要點（2026-10-18 讀碼確認）：`add` 以 `len(items) + 1` 產生 id，加入刪除後會產生重複 id（例：1、2、3 刪除 2 後再新增，得到第二個 id 3），導致 `done`／`delete` 作用到錯誤項目。

## 涉及檔案
- `todo.py` - 新增刪除與復原指令；新增項目的 id 改為不與現存及待復原項目重複
- `test_todo.py` - 新增刪除、復原、id 不重複的測試，以及既有新增／完成行為的刻畫測試
- `README.md` - 使用說明補上新指令（常青文件）
- `.gitignore` - 忽略待復原資料檔 `todo.undo.json`

## 驗收條件

1. **AC-1**：`python3 todo.py delete <id>` 後，列表不再出現該項目，其餘項目內容與順序不變 — 檢查方式：在暫存目錄新增三筆、刪除第 2 筆後列出，比對輸出
   - 失敗路徑：id 不存在時於 stderr 顯示錯誤、exit code 為 1，`todo.json` 內容不變
2. **AC-2**：`python3 todo.py undo` 只還原最近一次刪除的項目，id、標題、完成狀態與原位置都與刪除前相同；跨次執行仍有效。再次刪除會取代前一筆待復原項目（前一筆不可再復原） — 檢查方式：刪除前保存 `todo.json`，刪除後以獨立行程執行 `undo`，比對檔案內容完全一致；連刪兩筆後 `undo` 只還原第二筆
   - 失敗路徑：沒有可復原的項目（從未刪除，或已復原過）時於 stderr 顯示提示、exit code 為 1，資料檔不變
3. **AC-3**：刪除後再新增，新項目的 id 不與列表中或待復原的任何項目重複；`undo` 之後列表中不會出現重複 id — 檢查方式：新增 1、2、3，刪除 3，新增一筆，確認新 id 為 4；再 `undo`，確認列表 id 為 1、2、3、4 且無重複
   - 失敗路徑：出現重複 id 即判定失敗（後續 `done`／`delete` 會作用到錯誤項目）

## 風險與首要驗證

- **最大風險**：刪除後無法完整還原（id、完成狀態或位置跑掉），或刪除造成 id 重複，使後續操作作用到錯誤項目——兩者都等同使用者資料遺失或損毀
- **風險等級與理由**：High — 刪除是破壞性操作，復原失敗即資料遺失；既有 `len(items) + 1` 的 id 規則已確認會在刪除後產生重複
- **首要驗證**：先寫刪除→復原 round-trip 測試（比對 `todo.json` 刪除前後內容完全一致）與刪除後新增／復原的 id 不重複測試，取得紅燈；同時為既有 `add`／`done`／列表行為補刻畫測試並取得綠燈，確保 `todo.json` 格式不變
- **選擇理由**：最大失敗是資料不一致，直接比對資料檔內容最能證明還原完整；刻畫測試保護既有行為不因 id 規則調整而改變
- **完成證據**：round-trip 與 id 測試由紅轉綠、刻畫測試前後皆綠，`python3 -m unittest -v` 全綠
