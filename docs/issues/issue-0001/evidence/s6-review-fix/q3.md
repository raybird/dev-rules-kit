**Q2：`undo` 的語意**（影響 AC-1、AC-2）
- 建議：
  - 指令名用 `undo`。
  - 只能復原最近一次刪除。例如連刪 A、B 之後執行 `undo`，只會救回 B，再執行一次 `undo` 不會救回 A。
  - 復原後的 id、標題、完成狀態、列表中的位置都和刪除前一樣。
  - 刪除後中間做過 `add`、`done`，仍然可以 `undo` 那次刪除。
- 理由：這是「最後一次刪除」最直接的解讀，不需要額外的歷史紀錄。

**Q3：id 不重用**（影響 AC-3，這是最大風險）
- 建議：刪除的項目不會讓出 id。例如列表有 1、2、3，刪掉 2 之後新增一筆，新項目是 4；列表上會留一個空號。
- 理由：現在 `add` 用 `len + 1` 編號。如果刪除時直接把項目移出檔案，新項目會拿到和既有項目或待復原項目相同的 id。

**Q4：錯誤情況**（影響 AC-4）
- 建議：遇到下面兩種情況，都在 stderr 印出錯誤訊息、exit code 為 1，而且不改動 `todo.json`：
  - `delete` 指定的 id 不存在（含已刪除的 id）。
  - 沒有可復原的刪除時執行 `undo`。
- 另一個做法：像現有的 `done` 一樣什麼都不做，也不報錯。
- 理由：刪除是破壞性操作，打錯 id 卻沒有任何提示，使用者會以為刪成功了。

**Q5：輸出提示**（影響 AC-1、AC-2）
- 建議：
  - `delete` 成功時印出 `已刪除 2. 寫週報（可用 undo 復原）`。
  - `undo` 成功時印出 `已復原 2. 寫週報`。
- 另一個做法：和 `add`、`done` 一樣不輸出任何東西。
- 理由：刪除後讓使用者知道還能復原。
