# Issue 3103 - todo 刪除指令與復原最後一次刪除 (Small)

## 概述
新增 `delete <id>` 指令，並提供 `undo` 指令復原最後一次刪除的項目。

## 涉及檔案
- `todo.py` - 新增 `delete`、`undo` 指令；調整新增項目的 id 產生方式，避免刪除後 id 重複
- `test_todo.py` - 新增 AC-1～AC-5 的測試
- `README.md` - 使用說明加入 `delete`、`undo`（常青文件）
- `.gitignore` - 忽略可復原資料檔 `todo.undo.json`（TBD-3 結論）

## 驗收條件

1. **AC-1**：`delete <id>` 後列出清單不再出現該項目，其他項目的 id、標題、完成狀態不變 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：該項目仍在、其他項目被刪除或內容被改動，測試失敗。
2. **AC-2**：`undo` 復原最後一次刪除的項目；連續刪除 A、B 後執行 `undo`，只有 B 回到清單，A 不會被復原 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：B 未回到清單，或 A 也被復原，測試失敗。
3. **AC-3**：復原的項目保留原 id、標題、完成狀態與原本的列表位置；之後新增的項目不會重用任何既有 id，包含已刪除待復原的 id — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：清單 1、2 刪除 1 後新增，新項目 id 為 2（與既有項目重複）；或刪除 2 後新增再 `undo`，出現兩筆 id 2。
4. **AC-4**：刪除後執行 `add` 或 `done`，仍可 `undo` 復原該次刪除；只有下一次 `delete` 會取代可復原的項目 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：中間執行 `add`／`done` 後 `undo` 無法復原。
5. **AC-5**：`delete` 不存在的 id，或沒有可復原項目時執行 `undo`（含連續第二次 `undo`），在 stderr 印出錯誤訊息、exit code 1，`todo.json` 內容不變 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：exit code 為 0、無錯誤訊息，或資料被改動。

- **核准日期**: 2026-10-18（AC-1～AC-5）
- **核准來源**: 使用者 2026-10-18 對話原話「幫 todo 加刪除指令，而且刪除後要可以復原。」（AC-1、AC-2）；問題 1 回答「只要能復原最後一次刪除就好」（AC-2，選定只復原最後一次刪除）；問題 2～4 回答「照建議」，接受建議答案：問題 2 錯誤時 stderr 訊息、exit 1、資料不變（AC-5），問題 3 復原保留原 id 與位置且新增不重用 id（AC-3），問題 4 中間執行 `add`／`done` 仍可 `undo`、可復原資料另存 `todo.undo.json`（AC-4）
- **核准 commit**: 待提交

## 風險與首要驗證

- **最大風險**：刪除後新增項目產生重複 id（現行 `add` 以 `len(items) + 1` 產生 id），導致 `done`／`delete`／`undo` 誤動到另一筆資料。
- **風險等級與理由**：High — 刪除是資料損失操作，id 重複會讓後續操作影響錯誤的項目。
- **首要驗證**：先寫「刪除後新增 id 不重複」「刪除只影響指定項目」的失敗測試（回歸測試網），再實作刪除。
- **選擇理由**：id 重複可由單元測試直接重現，比其他手段更直接證明誤刪風險已排除。
- **完成證據**：上述測試先紅（重複 id 或指令不存在）後綠，且既有 `test_render_marks_done` 維持通過。
