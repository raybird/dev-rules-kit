# Issue 3102 - 待辦到期提醒 (Small)

## 概述
讓每個待辦可以設定到期時間（本機時間，精確到分鐘）；每次執行 todo 指令時檢查，已到期且未完成的項目在輸出最前面提醒。不使用常駐程序。

## 涉及檔案
- `todo.py` - 新增 `due` 指令、到期欄位、提醒輸出、清單顯示到期時間、錯誤處理
- `test_todo.py` - 新增 AC-1～AC-4 的測試
- `README.md` - 使用說明補上 `due` 指令與提醒行為（常青文件，依 project.md）

## 驗收條件

1. **AC-1**：`python3 todo.py due <id> <YYYY-MM-DD HH:MM>` 為既有待辦設定到期時間；對同一筆再次執行時改成新的時間。其他欄位與其他待辦不變。 — 檢查方式：`python3 -m unittest -v` 中標注 AC-1 的測試，執行指令後讀取 `todo.json` 比對
2. **AC-2**：每次執行任一 todo 指令（列出、`add`、`done`、`due`）時，每一筆「已設定到期時間、輸出當下尚未完成、到期時間 ≤ 現在」的待辦，都會在該指令其他輸出之前印出一行 `⏰ 已到期：<id>. <標題>（到期 YYYY-MM-DD HH:MM）`。已完成或未設定到期時間的待辦不提醒；未完成的到期項目每次執行都會再提醒。 — 檢查方式：標注 AC-2 的測試，以固定的「現在」時間驗證到期／未到期、已完成、未設定，以及剛好等於到期時間的邊界
3. **AC-3**：列出清單時，有到期時間的待辦在標題後顯示 `（到期 YYYY-MM-DD HH:MM）`；沒有到期時間的待辦（含舊 `todo.json` 中沒有到期欄位的資料）顯示方式不變。 — 檢查方式：標注 AC-3 的測試，加上既有 `test_render_marks_done` 必須維持通過
4. **AC-4**：`due` 的時間不符合 `YYYY-MM-DD HH:MM`（含不存在的日期），或指定的 id 不存在時，在 stderr 印出錯誤訊息，以結束碼 1 結束，`todo.json` 內容不變。 — 檢查方式：標注 AC-4 的測試，比對結束碼、stderr，以及執行前後的 `todo.json`

  - Q1（提醒方式，AC-2）：「每次執行 todo 指令時檢查並在輸出前顯示，不要常駐程序」
  - Q2～Q5（AC-1～AC-4）：「Q2 時間到分鐘，格式 YYYY-MM-DD HH:MM；其他照建議」。其中 Q2 的建議是 `due <id> <時間>` 指令、以本機時間計算、重複執行即修改；Q3 的建議是只提醒未完成且到期時間 ≤ 現在的項目，每次執行都提醒；Q4 的建議是提醒行格式與清單附註到期時間；Q5 的建議是錯誤時印到 stderr、結束碼 1、不改資料。
