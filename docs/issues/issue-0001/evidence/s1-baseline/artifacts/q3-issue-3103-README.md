# Issue 3103 - 待辦刪除指令與復原最後一次刪除 (Small)

## 概述
新增 `delete <id>` 刪除待辦，並以 `undo` 復原最後一次刪除的項目。只保留最後一次刪除，不提供多層復原或依 id 復原。

## 涉及檔案
- `todo.py` - 新增 `delete`、`undo` 指令；新增 id 改為不與既有及可復原項目重複
- `test_todo.py` - 新增 AC-1～AC-5 的測試
- `README.md` - 使用說明補上 `delete`、`undo`（常青文件，依 project.md）
- `.gitignore` - 忽略復原紀錄檔 `todo.undo.json`

## 驗收條件

1. **AC-1**：`delete <id>` 後，`python3 todo.py` 列表不再出現該項，並輸出 `已刪除 <id>. <標題>（可用 undo 復原）` — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：列表仍顯示該項，或誤刪其他項目，即判定失敗
2. **AC-2**：刪除後執行 `undo`，該項以原 id、標題、完成狀態回到原本的列表位置；成功復原後復原紀錄清空 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：復原後 id、標題、完成狀態或位置任一與刪除前不同，即判定失敗
3. **AC-3**：連續刪除 A、B 後執行 `undo`，只有 B 復原，A 維持刪除 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：A 被復原，或 B 未復原，即判定失敗
4. **AC-4**（最大風險）：刪除後再 `add`，新項目的 id 不與現存項目或可復原項目重複；之後 `undo` 與 `done <id>` 都只影響單一項目 — 檢查方式：`python3 -m unittest -v`，情境「1、2、3 → delete 3 → add → undo → done 新 id」
   - 失敗路徑：出現重複 id，或 `done` 同時標記兩筆，即判定失敗
5. **AC-5**：`delete` 不存在的 id、`undo` 時沒有可復原項目（含連續兩次 `undo`），在 stderr 輸出錯誤訊息（如 `找不到 id 5`、`沒有可復原的刪除`）、exit code 為 1，`todo.json` 內容不變 — 檢查方式：`python3 -m unittest -v`
   - 失敗路徑：exit code 為 0、沒有錯誤訊息，或 `todo.json` 被改動，即判定失敗

## 風險與首要驗證

- **最大風險**：`add` 以 `len(items) + 1` 產生 id（`todo.py:20`），真的移除項目後會配出重複 id，`done <id>` 會一次標記兩筆；復原時還可能與新項目撞號，造成資料錯亂
- **風險等級與理由**：High — 刪除與復原直接牽涉使用者資料遺失與損毀
- **首要驗證**：先寫 AC-4 的回歸測試（刪除 → 新增 → 復原 → done），確認 id 不重複，再實作其他指令
- **選擇理由**：這是既有行為可能被破壞的風險；回歸測試能直接重現撞號，比其他手段更直接
- **完成證據**：AC-4 測試先因缺少目標行為而紅燈，實作後轉綠，且既有 `RenderTest` 仍通過
