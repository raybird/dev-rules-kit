# Issue 3102 - 待辦到期提醒 (Small)

## 概述
每個待辦可以設定到期時間（`YYYY-MM-DD HH:MM`，本機時間，精確到分鐘）。每次執行 todo 指令時檢查，若有已到期且未完成的待辦，先顯示提醒再顯示指令本身的輸出；不使用常駐程序。

## 涉及檔案
- `todo.py` - 新增 `due` 指令、到期判定、提醒輸出，列表顯示到期時間
- `test_todo.py` - 新增 AC-1～AC-6 的測試
- `README.md` - 使用說明補上 `due` 指令與提醒行為（常青文件）

## 驗收條件

測試中的「目前時間」須由測試控制，不依賴真實時鐘。

1. **AC-1**：`python3 todo.py due <id> <YYYY-MM-DD HH:MM>` 將該待辦的到期時間存入 `todo.json`；對同一 id 再次執行則覆蓋舊值 — 檢查方式：單元／CLI 測試設定兩次後讀回資料，只留第二次的值
2. **AC-2**：列表中有到期時間的待辦於該行顯示到期時間；沒有到期時間的待辦輸出與現行完全相同（既有 `todo.json` 不需轉換） — 檢查方式：既有 `test_render_marks_done` 維持原樣通過，另以含到期時間的資料斷言字面輸出
3. **AC-3**：執行任何指令（列出、`add`、`done`、`due`）時，若存在「目前時間 ≥ 到期時間」且未完成的待辦，提醒列在該指令自身輸出之前顯示；到期時間恰等於目前時間（同一分鐘）即算到期，早一分鐘不算 — 檢查方式：固定目前時間，分別執行四種指令並斷言輸出開頭的提醒內容與順序，含邊界值
4. **AC-4**：時間格式錯誤（例如 `2026/10/20 18:00`、`2026-13-01 25:00`、缺少時間部分）時，stderr 顯示錯誤原因、exit code 為 1，`todo.json` 內容不變 — 檢查方式：測試比對執行前後檔案內容與 exit code
5. **AC-5**：`due` 指定不存在的 id 時，stderr 顯示錯誤原因、exit code 為 1，`todo.json` 內容不變 — 檢查方式：同 AC-4
6. **AC-6**（待核准）：已完成的待辦即使已到期也不提醒；提醒反映本次指令執行**之後**的狀態（例如 `done` 一個已到期的待辦後，它不出現在本次提醒中）；`due` 出錯時只輸出錯誤、不顯示提醒 — 檢查方式：固定目前時間，斷言上述三種情況的輸出

- **核准日期**: 2026-10-18（AC-1～AC-5）
- **核准來源**: 2026-10-18 對話逐題確認——原始需求「每個待辦可以設到期時間，到期時要提醒我」；Q1 使用者原話「每次執行 todo 指令時檢查並在輸出前顯示，不要常駐程序」（AC-3）；Q2「到分鐘，格式 YYYY-MM-DD HH:MM」，時區沿用建議的本機時間（AC-1、AC-3、AC-4）；Q3「照建議」＝新增 `due <id> <時間>`、重複設定覆蓋、`add` 不變（AC-1、AC-2）；Q4「照建議」＝格式錯誤與 id 不存在皆報錯、exit 1、資料不變（AC-4、AC-5）。AC-6 為規劃時推導的假設，等待確認（TBD-1）
