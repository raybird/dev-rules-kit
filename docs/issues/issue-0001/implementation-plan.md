## 測試策略

本輪產品是 agent 會讀的規則，行為驗證採隔離專案與宿主的新 session；靜態檢查只證明文件與腳本結構有效，不能代替 agent 行為驗收。這些案例沒有不同的底層程式邏輯責任，採一組宿主行為對比承擔驗收與回歸，不另建鏡像單元測試；若實作確認需修改腳本，再為該腳本獨立失敗面補測。

沿用既有 WF-19～WF-24 的相關情境，補充缺少的正反對照，而非全面重跑無關流程。基準組與候選組使用相同輸入、fixture、工具權限、宿主／模型設定；版本差異僅限已核准規則及其必要引用。完整輸出與預期分開保存，測試 agent 不接收預期答案。

| 驗收 | 行為案例與完成證據 |
|---|---|
| SCN-001 | 獨立可簡答且不影響後題時預設合併、獨立但複雜的取捨逐題、前題決定後題、有明確逐題偏好、已有授權、需核准新增行為。以腳本化使用者回答比較完整對話；合併案例計算完成相同決策所需回覆數，不把略過問題算成減負 |
| SCN-002 | 有／無前綴但同去向、有效結構化去向、欄位空但原文有明確去向、來源矛盾、具體且與範圍相關的不追蹤理由、只有「這個不重要」或「以後再說」、有不追蹤理由但必要驗收未豁免、真正無去向及不存在／無權限確認目標。比對實際結果與事先人工定義的正解及證據來源；必要驗收缺漏仍須列出，相同輸入的結論差異明列為不穩定，不能只挑成功輪次 |
| SCN-003 | 必要驗收未執行、僅文件狀態落差、平台未知、正常進行、專案合法排除、專案排除與未豁免必要驗收衝突、有明確豁免、合法純文件交付及僅合併佔位紀錄。核對九類原因、三種行動層級與建議；已知缺漏和其他未知並存時仍列出已知缺漏。比對查詢前後工作樹、HEAD 及平台 fixture 狀態 |
| SCN-004 | 彙整前述對比，記錄人工回覆數、錯誤阻塞、誤報、必要 gate 漏檢及同義規則的權威維護位置。任一必要 gate 漏檢即為回歸失敗，不以互動改善抵換。正確性依獨立預期判定，不以字數或命令 exit code 當 agent 行為成功 |

具體規則失效先在基準組呈現可指認的失敗，再驗候選組消除問題；可合併這類允許式規則若只從單輪看不出差異，保留未知，不編造紅燈。行為未通過時回到實際失敗原因，避免以新增例外條文掩蓋不穩定性。字數僅作成本資訊。
