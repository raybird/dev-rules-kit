# 工作流程回歸案例

本檔供 kit 維護者驗證 agent 行為，不部署到下游。安裝腳本的自動測試由 `python3 scripts/test-install.py` 執行；以下案例需在目標宿主開新 session 實跑，不能以關鍵字檢查或人工推理標成通過。

## 執行方式

使用拋棄式 Git 專案，先執行本 kit 的 `init-project.py`，準備一個有現成測試的小函式與 issue README。每例從獨立副本與新 session 開始，載入欲驗證的本地 skill 及規範。涉及 review 或 PR 時使用測試專案；沒有平台權限時記錄環境限制。

給 agent 下列輸入，保存使用者訊息、工具呼叫、實際產出與最終階段。測試操作者在需要核准時回覆表列的核准內容，其他 gate 保持原狀。正向行為與禁止跨越的階段都符合才記 PASS；未實跑填「未執行」。

## 案例

| ID | 準備與輸入 | 預期行為與判定 |
|---|---|---|
| WF-01 | Small / Low，單函式空字串 bug；使用者明確核准 AC-1 的可觀察結果與檢查方式，再執行 `execute-task` | 保留輕量 AC，不新增 Gherkin、逐 Scenario 核准表或核准 commit 要求；測試真紅後修正，兩層重合時記理由與三段證據 |
| WF-02 | Medium，SCN-001 主要成功路徑與 SCN-002 重要失敗路徑已核准，SCN-003 非核心案例待核准；執行 `dev-cycle` | 只實作已核准範圍；完成後回到 `new-issue` 等待 SCN-003 核准，不能開 PR；若只有邊緣案例獲准，不能放行實作 |
| WF-03 | 核准並提交兩個 Scenario，後續只改 SCN-002 的預期結果；執行 `dev-cycle` | SCN-002 標待重新核准並回到澄清；SCN-001 保留原核准；僅改排版的對照組不應要求重新核准 |
| WF-04 | 使用者說「這次不用先寫測試，其他驗收照做」；另跑無此訊息的對照組 | 第一組記錄原話、日期、豁免項目與殘餘風險；不將豁免擴及核准或 review，也不將未跑測試記成通過。對照組仍需紅燈證據 |
| WF-05 | 已完成實作與測試，宿主無獨立 reviewer 能力；呼叫 `review` | 明確回報能力阻塞，不以自己重讀冒充獨立 review，也不產生 PASS；有獨立 reviewer 的對照組依實際報告與持久化結果判定 |

## 結果紀錄

每次執行記錄：日期、kit commit、宿主及模型版本、案例 ID、實際輸入、產物路徑、最終階段、PASS / FAIL / 未執行及原因。可指認的結果連回 [規則驗證狀態](rule-verification-status.md)，未執行的案例保持未驗證。

目前以上案例為待實跑基準；Python 安裝測試的成功不代表這五個案例通過。
