> 本 skill 需要 `docs/AGENTS.md` **流程契約 2.0**；相容性依該檔「核心層齊備性檢查」。

## 輸入

取得 issue、權威任務來源、指定步驟／Task、已核准驗收與風險策略。dev-cycle 傳入時直接使用；獨立呼叫未指定項目時可選計畫中第一個已核准、相依滿足的未完成項目並說明。真正缺少完成判準或必要決策才回到規劃。

讀 AGENTS.md、agents/project.md、agents/acceptance.md 與 agents/verification.md。Small 的任務在 README，Medium／Large 在 implementation-plan.md；舊 issue 沿用 README 指向的唯一 Decomposition。

## 執行

1. **準備範圍**：確認目前分支與使用者未提交內容；在主幹時依 project.md 建 issue 分支，已有正確工作分支則沿用。只處理該 Task 的必要模組。
2. **核對契約**：依 acceptance.md 比對核准基線與實際工作區，確認本 Task 及其相依已核准。受其他待核准 Task 阻塞時列出原因；無相依者繼續。新必要行為先取得核准，等價的命令與路徑選擇自行完成。
3. **探索與驗證設計**：確認現有行為及最直接的測試入口。行為變更依 verification.md 取得真實紅燈，再最小實作至綠燈；外層與內層保障相同時合併紅燈並記理由。純重構用前後同組綠燈；文件使用靜態／人工證據；生產觀測先驗證判準的反向自檢。
4. **精煉**：綠燈後依 code-simplify 檢查本次變更一次。有實質改善才修改並重跑受影響檢查；no-op 保留既有有效證據，不為完成此步造修改。
5. **交付驗證**：逐項核對完成判準、假綠燈與風險證據。依變更執行必要 build／test／lint 等檢查；同內容與環境已有有效結果可引用。限制、未執行項目與豁免照實記錄。
6. **回寫**：證據持久化於原任務項目或 artifact；每項驗收編號指向該證據。必要項全數通過才標已完成；按 project.md 更新受影響的常青文件，語意事件記 Timeline。寫入失敗則保持未完成。

## 完成判準與輸出

Task 的產出、驗收、必要檢查及文件回寫都已完成，且修改範圍與授權一致。單獨執行本 skill 不自動提交；dev-cycle 負責後續提交與 PR。

只回報：Task 與實際結果、主要修改、證據位置、未解決阻塞／殘餘風險。完整命令輸出保留於權威證據，不在對話重複整份報告。
