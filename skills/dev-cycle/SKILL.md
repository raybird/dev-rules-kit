> 本 skill 需要 `docs/AGENTS.md` **流程契約 2.0**；相容性依該檔「核心層齊備性檢查」。

## 輸入與模式

取得 issue ID；缺少且無法從目前對話辨認才詢問。主要意圖為查狀態時採查詢；明確要求繼續、處理或推進時採推進，即使同時要求回報進度也一樣。

讀 README、任務來源、Git／PR 與持久化證據，再依 AGENTS.md 讀本次分支的參考檔。**偵測是唯讀操作**：缺欄位、版本落差或失效基線都回傳待處理事項，不補寫文件、不改核准狀態、不建立 branch。查詢只回報階段、依據、缺項與下一步，然後結束。

## 任務來源

讀 metadata 的 `**分級**` 開頭詞；Small 使用 README「實作與驗證步驟」，Medium / Large 使用 implementation-plan.md；Large 在同檔維護 Phase / Task。舊 issue 若 README 明確指向獨立 Decomposition，沿用該唯一來源並補拆在原檔，不建立第二份清單。

缺分級時依內容與影響範圍評估，不以檔案形狀當定論。查詢回報未知與建議；推進可根據明確內容補寫分級／風險並記理由，只有足以改變範圍或驗證策略的歧義才問使用者。

## 狀態偵測

先辨識生命週期，再查該階段適用的 gate：

| 條件（由上而下） | 下一步 |
|---|---|
| PR 已 merged | 結案；不以歷史核准 SHA 或舊任務缺件重啟實作 |
| 狀態為 `不修復` | 核對 AGENTS.md 規定的決策紀錄及獨立決策審查／豁免；缺件補決策紀錄或 review，齊備則保留不修復終態 |
| 狀態為 `已完成` 且有其他可追溯的核准結案依據，所需決策審查／豁免齊備 | 按實際依據結案；不記不存在的 merge |
| 狀態為 `等待外部驗收窗` 且窗口前工作已有證據 | 窗口未到則回報並結束；到達則僅執行待觀察項目；窗口／判準缺漏先補明 |
| README 不存在，或無法辨認必要驗收規格與核准來源 | new-issue |
| 適用契約／基線缺漏或不相容 | 準備遷移或恢復證據；只暫停依賴該缺項的操作 |
| Large 有已核准但尚無責任 Task 的 Scenario，或修訂使對應計畫失效 | decompose，在權威計畫補齊或修訂映射 |
| 有已核准、相依已滿足而未完成或缺有效證據的 Task | execute-task，自動選計畫順序中的第一項；使用者指定項目時先檢查其相依 |
| 無可執行 Task，仍有待核准／待重新核准項目 | new-issue，只處理待決定部分 |
| 所有條件已核准，但仍有未完成且無可執行的 Task | 回報具體相依阻塞，不把它當成已完成 |
| 任務全部完成但交付變更尚未提交 | 依 create-commit 準備並提交已授權的交付內容 |
| 無 open PR，或 PR 範圍／Proof of Test 與交付版本不一致 | create-pr，建立或更新 |
| 沒有符合 review-evidence.md 有效性規則的持久化報告 | review |
| 有效 review 為 RETURN TO execute-task | 修正問題、更新證據與提交，再審查新範圍 |
| 有效 review 為 PASS | 等待合併，回報後結束本次調用 |

已知必要工作未完成時，等待狀態不能遮蔽它，繼續走下方任務分支。規格變更先依 acceptance.md 比對工作區；偵測只指出受影響項目，推進才回寫。其他 Scenario 待重新核准不阻塞無相依的已核准 Task。

`## Gate 豁免紀錄` 只放行明列 gate。`## 待確認事項` 是揭露機制，非阻塞未知不改寫成已解決以推進。獨立 review 被明確豁免時，揭露「未獨立審查」後可等待合併，不偽造 PASS。

## 推進與完成條件

1. 回報目前階段與下一步；已授權的計畫由協調者自動選 Task 並傳入完整輸入。
2. execute-task 在內部完成 code-simplify 與驗證，協調者再依 create-commit 規範提交。交付範圍依 review-evidence.md 固定 BASE／HEAD，再傳給 create-pr 與 review；新提交後重新取得範圍。
3. 依既有授權建立／更新 PR，獨立審查後保存 artifact。遇到新需求決策、權限限制或真實阻塞才停止；不重問已回答的 Task 選擇與核准。
4. 有實質狀態變化才重新偵測。等待窗口、等待合併、等待必要回答或同一阻塞未變時回報並結束，不忙迴圈、不自行合併 PR。
5. 真實 merge 後標記已完成並記實際 merge 日期；不修復保留原狀態與決策日期；其他核准結案記實際依據。文件收尾不得被描述成程式測試或 merge。

每次輸出：issue、目前階段、本次完成內容與證據位置、下一步或阻塞。完成判準是該階段證據與狀態已一致；不能只憑 branch／commit 名稱含 issue ID 就判定完成。
